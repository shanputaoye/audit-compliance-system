1 项目概述

1.1 产品定位

一句话定义：面向军工/政府/大型企业项目验收审计场景的指标闭环检查专用工具。

本产品不是通用项目管理软件，而是聚焦于项目验收阶段最核心的痛点——如何系统性地验证"需求→方案→实施→验证→闭环"的指标追溯链路完整性。它将当前以 Excel + Word 手工对账为主的审计流程，升级为结构化、可视化、可追溯的数字化工作流。

1.2 核心价值主张

维度现状（手工）本产品提升
指标覆盖检查逐条比对Excel，易遗漏自动闭环状态判定+断点高亮杜绝遗漏
证据追溯散落各文件夹/邮件每阶段关联证据+日期+版本一键追溯
审计报告手工编写，半天到一天一键生成结构化Word报告效率10x+
多人协作文件传来传去局域网共享+权限控制协作可控
历史追溯几乎没有全量操作日志+版本记录审计合规

1.3 目标用户与环境

项目约束/要求
操作系统Windows 7（主）/ Windows 10+（辅）
浏览器IE11、旧版Edge（EdgeHTML）、Firefox ESR 115
网络环境内网/离线为主，部分场景局域网共享
用户规模Phase 1：1-3人单机；Phase 2：5-15人局域网协作；Phase 3：50+内网服务
数据安全全本地存储，不上传云端，SQLite文件支持AES加密
AI辅助可选集成内部DeepSeek（非必需），有降级方案

2.2 技术栈选型（Win7 兼容验证）

层级技术版本Win7兼容选型理由
后端框架Python + Flask3.8.10 / 2.2.x 完全支持 Python 3.8 是最后一个官方支持Win7的版本；Flask 2.x 兼容 3.8
数据库SQLite3内置 完全支持 Python内置，零安装，文件级管理；WAL模式支持并发读
前端框架Vanilla JS + Bootstrap 3ES5 / 3.4 完全支持 Bootstrap 3 是最后一个支持IE11的版本；ES5语法全兼容
Word报告python-docx0.8.11 完全支持 纯Python实现，不依赖系统Office
Excel导入openpyxl3.0.10 完全支持 支持.xlsx读写，含样式和数据验证
打包工具PyInstaller4.10 完全支持 打包为单个.exe，含Python解释器+依赖库+前端静态文件
加密pycryptodome3.15 完全支持 SQLite文件AES-256加密
AI接口requests + OpenAI SDK基础 完全支持 调用内部DeepSeek API，有超时降级和缓存

2.3 Win7 前端兼容策略

场景浏览器JS引擎兼容方案
场景A（最佳）旧版Edge (EdgeHTML 18)Chakra 支持大部分ES6，可保留模板字符串和箭头函数，只需避免ES2017+特性
场景B（兼容）Firefox ESR 115SpiderMonkey 完整支持ES6+，开发体验最接近现代浏览器
场景C（最差）IE11Chakra (旧) 必须降级到ES5：var代替const/let，普通函数代替箭头函数，字符串拼接代替模板字符串，XMLHttpRequest代替fetch

关键决策点：开发启动前必须确认目标客户Win7机器的实际浏览器版本。如果多数客户有旧Edge或Firefox，开发成本降低40%以上。如果必须兼容IE11，需要额外2-3周做ES5降级和Polyfill。

3.2 核心表建表SQL

-- ===== 项目表 =====
CREATE TABLE project (
    id          TEXT PRIMARY KEY,
    name        TEXT NOT NULL,
    code        TEXT,                    -- 项目编号
    description TEXT,
    status      TEXT DEFAULT 'active',  -- active/archived
    start_date  TEXT,
    end_date    TEXT,
    template    TEXT,                    -- 模板类型: military/gov/enterprise
    created_by  TEXT,
    created_at  TEXT DEFAULT (datetime('now','localtime')),
    updated_at  TEXT
);

-- ===== 指标表 =====
CREATE TABLE indicator (
    id            TEXT PRIMARY KEY,
    project_id    TEXT NOT NULL REFERENCES project(id),
    module        TEXT NOT NULL,           -- 所属模块
    name          TEXT NOT NULL,           -- 指标名称
    target_value  TEXT,                    -- 目标值/要求
    actual_value  TEXT,                    -- 实际值
    owner         TEXT,                    -- 负责人
    description   TEXT,
    category      TEXT,                    -- 类别tag
    sort_order    INTEGER DEFAULT 0,
    created_at    TEXT DEFAULT (datetime('now','localtime')),
    updated_at    TEXT
);

-- ===== 阶段记录表（核心）=====
CREATE TABLE stage_record (
    id              TEXT PRIMARY KEY,
    indicator_id    TEXT NOT NULL REFERENCES indicator(id) ON DELETE CASCADE,
    stage_key       TEXT NOT NULL,        -- requirement/design/implementation/verification/closure
    status          TEXT DEFAULT 'pending', -- pending/done/issue
    description     TEXT,
    evidence        TEXT,
    evidence_file_id TEXT,
    completed_date  TEXT,
    updated_by      TEXT,
    updated_at      TEXT DEFAULT (datetime('now','localtime')),
    UNIQUE(indicator_id, stage_key)
);

-- ===== 需求-方案对照表 =====
CREATE TABLE req_mapping (
    id            TEXT PRIMARY KEY,
    project_id    TEXT NOT NULL REFERENCES project(id),
    req_clause    TEXT,                    -- 招标条款编号
    req_content   TEXT,                    -- 招标要求内容
    resp_section  TEXT,                    -- 响应方案章节
    resp_content  TEXT,                    -- 响应方案内容
    status        TEXT DEFAULT 'pending',  -- done/partial/missing
    notes         TEXT
);

-- ===== 用户表 =====
CREATE TABLE user (
    id            TEXT PRIMARY KEY,
    username      TEXT UNIQUE NOT NULL,
    password_hash TEXT NOT NULL,
    role          TEXT DEFAULT 'viewer',   -- admin/editor/viewer
    display_name  TEXT,
    created_at    TEXT DEFAULT (datetime('now','localtime'))
);

-- ===== 审计日志表 =====
CREATE TABLE audit_log (
    id          TEXT PRIMARY KEY,
    user_id     TEXT,
    action      TEXT NOT NULL,           -- create/update/delete/export
    target_type TEXT,                    -- indicator/stage/project
    target_id   TEXT,
    detail      TEXT,                    -- JSON格式变更明细
    ip_address  TEXT,
    created_at  TEXT DEFAULT (datetime('now','localtime'))
);

-- 索引
CREATE INDEX idx_indicator_project ON indicator(project_id);
CREATE INDEX idx_stage_indicator ON stage_record(indicator_id);
CREATE INDEX idx_audit_log_time ON audit_log(created_at);
CREATE INDEX idx_req_mapping_project ON req_mapping(project_id);

5 分阶段详细开发任务

Phase 1 — 工程可用版（MVP）

⏰ 周期：4周👥 人力：1人（全栈）🎯 目标：可演示、可在Win7运行的单机版

Week 1: 后端基础 + 数据库

  • 1
    项目骨架搭建
    Flask应用初始化、配置管理（config.py）、蓝图注册、错误处理中间件、CORS配置。使用waitress作为WSGI服务器（Windows兼容好的纯Python实现）。
  • 2
    数据库初始化
    按3.2建表SQL创建SQLite数据库，实现db.py模块（连接管理、WAL模式开启、迁移脚本）。编写seed_data.py导入默认项目数据。
  • 3
    指标管理API
    实现指标的 GET/POST/PUT/DELETE 全套接口，含搜索、筛选、排序、分页。输入校验（名称必填、模块枚举等）。
  • 4
    阶段管理API
    实现五阶段的状态更新接口，含闭环状态自动判定逻辑（done×5→closed，首个pending/issue→断点定位）。

Week 2: 前端重构（Win7兼容）

  • 5
    ES5前端脚手架
    搭建 Bootstrap 3 + Vanilla JS 前端工程。配置 Gulp/Webpack 做 ES6→ES5 Babel 转译 + CSS Autoprefixer。部署为 Flask static 目录下的静态资源。
  • 6
    页面骨架+导航
    实现左侧导航栏、顶部工具栏、路由切换。7个页面骨架：项目总览、六大模块、指标矩阵、闭环追踪、需求对照、审计报告、风险清单。
  • 7
    仪表盘页面
    调用 /api/dashboard 渲染统计卡片、五阶段进度条、闭环分布图。纯CSS图表（避免Canvas/Chart.js在IE11的兼容问题）。
  • 8
    指标管理页面
    列表表格+搜索/筛选/分页，新增/编辑模态框，删除确认。表格中的五阶段状态用圆点可视化。

Week 3: 核心功能 + 报告

  • 9
    闭环追踪页面
    左右分栏：指标列表 + 五阶段详情卡片。每阶段卡片含状态标签/描述/证据/日期/编辑按钮。断点处红框高亮+阻断提示。
  • 10
    需求-方案对照页面
    表格形式展示招标要求⇄方案响应的对照关系，支持新增/编辑对照条目。覆盖状态用颜色标记。
  • 11
    审计报告生成
    后端：python-docx 生成结构化Word报告（封面→闭环概览→五阶段明细→断点清单→需求覆盖表→建议）。前端：预览+下载按钮。
  • 12
    数据导入导出
    JSON格式的完整数据导入导出（项目+指标+阶段+对照表）。前端下载/上传文件触发。

Week 4: 打包 + 测试 + 交付

  • 13
    PyInstaller打包
    打包为单个 audit-checker.exe。含 Flask应用、waitress服务器、所有依赖库、static前端文件、默认SQLite数据库。配置 --onedir 模式避免启动慢。
  • 14
    启动器开发
    .exe 启动后自动启动 Flask + 打开默认浏览器访问 localhost:8899。托盘图标+右键菜单（打开/关于/退出）。
  • 15
    Win7真机测试
    在Win7虚拟机/真机上安装运行，验证：Python环境、浏览器兼容（IE11/Edge/Firefox）、编码问题（中文路径/文件名）、长时间运行稳定性。
  • 16
    用户手册初版
    编写《快速入门指南》，含安装步骤、基本操作流程、常见问题。Word格式，10页以内。

Phase 2 — 企业协作版

⏰ 周期：8周👥 人力：2人（1后端+1前端）🎯 目标：支持多人协作、权限管理、模板化

Sprint 1 (W5-6): 用户与权限

  • 17
    用户认证系统
    登录/登出/密码修改。使用 bcrypt 哈希存储密码。Session管理（Flask-Login或自研简单token）。
  • 18
    三级权限控制
    admin（全部权限）/ editor（编辑本项目）/ viewer（只读）。前端按钮显隐+后端API权限中间件。
  • 19
    审计日志
    记录所有CUD操作到audit_log表，含操作人、操作类型、目标对象、变更前后对比（JSON diff）、IP、时间。

Sprint 2 (W7-8): 协作与项目模板

  • 20
    局域网共享模式
    一台机器启动Flask服务，其他同网段机器通过IP:8899访问。SQLite WAL模式支持3-5人并发读写。文件锁机制防写冲突。
  • 21
    项目模板系统
    预设3类模板（军工武器装备/政府信息化/企业IT项目），含标准模块和指标清单。创建项目时选择模板自动初始化。
  • 22
    Excel批量导入
    按模板Excel格式批量导入指标。openpyxl读取+校验+逐条插入，错误行高亮返回。支持更新模式（匹配name覆盖）。

Sprint 3 (W9-10): 证据与报告增强

  • 23
    证据附件管理
    支持上传PDF/图片/文档作为阶段证据，存储到本地 evidence/ 目录。前端缩略图预览+下载。文件大小限制10MB。
  • 24
    Word报告模板引擎
    基于 jinja2 + python-docx 实现可配置的报告模板。支持封面信息、统计图表(图片嵌入)、条件段落（有断点/无断点不同措辞）。
  • 25
    批量操作
    批量更新阶段状态（全选→标记完成）、批量导出（选中指标导出Excel）、批量删除（选择+确认）。

Sprint 4 (W11-12): 通知与打磨

  • 26
    预警与通知
    交付节点到期前7天桌面通知（Windows toast notification via win10toast/pywin32）。断点指标统计面板实时更新。
  • 27
    UI/UX打磨
    全页面响应式适配（1024/1366/1920）。加载状态骨架屏。空状态引导提示。键盘快捷键（Ctrl+S保存、Esc关闭弹窗）。
  • 28
    测试+文档
    编写50+功能测试用例。用户手册升级为完整版（含权限说明、模板定制、批量操作）。制作5分钟操作演示视频。

Phase 3 — 平台增强版

⏰ 周期：持续迭代👥 人力：2-3人🎯 目标：内网B/S部署、AI辅助、API开放
  • 29
    内网B/S架构升级
    部署到Linux/Windows Server。Gunicorn + Nginx反向代理。PostgreSQL替代SQLite（可选）。支持50+并发用户。Session+JWT双认证。
  • 30
    DeepSeek集成
    招标文件上传→DeepSeek解析→自动提取指标项+条款编号→人工确认后入库。审计建议生成（"该指标验收验证阶段尚未完成，建议补充..."）。
  • 31
    审计知识库
    积累历史项目的审计模式、常见断点类型、典型整改措施。新项目创建时智能推荐检查清单。
  • 32
    API开放平台
    RESTful API文档（Swagger/OpenAPI）。供PLM/ERP/测试管理工具调用，实现指标数据自动同步。
  • 33
    信创适配
    麒麟/统信操作系统适配。达梦/人大金仓数据库驱动。东方通中间件。通过信创符合性测试。

9 部署方案

9.1 Phase 1 部署（单机版）

步骤操作产出
1. 打包PyInstaller --onedir --add-data "static;static" --add-data "templates;templates" app.pydist/audit-checker/ 目录
2. 制作安装包Inno Setup脚本：复制dist目录到 Program Files、创建开始菜单快捷方式、注册卸载程序audit-checker-setup.exe
3. 安装用户双击 setup.exe → 选择安装路径 → 完成C:\Program Files\AuditChecker\
4. 启动桌面快捷方式 → audit-checker.exe 启动 → Flask 监听 127.0.0.1:8899 → 自动打开浏览器浏览器显示登录/仪表盘
5. 数据位置用户数据（数据库、证据文件、导出报告）存储在 %APPDATA%\AuditChecker\备份直接复制该目录

9.2 Phase 2 部署（局域网协作）

模式说明适用场景
单机主机模式一台机器运行服务，监听 0.0.0.0:8899。其他机器浏览器访问 http://主机IP:8899。SQLite WAL模式支持并发读。3-5人小团队，同一办公室
共享文件夹模式SQLite数据库文件放在局域网共享目录。各机器运行自己的Flask实例但指向同一个db文件。文件锁防写冲突。网络不稳定，需要离线能力

10 风险管理矩阵

#风险概率影响等级缓解措施触发条件与预案
R1IE11兼容性导致前端大量返工中高高 Phase1启动前确认浏览器版本。优先推动客户安装Firefox ESR（免费、Win7支持）。准备好ES5降级方案。 Week1浏览器确认。如必须IE11 → 延期2周做降级
R2SQLite并发写冲突导致数据丢失低高中 Phase 2 实施 WAL模式+重试机制。写操作加乐观锁（版本号比对）。 如并发写入>5人 → 考虑迁移PostgreSQL
R3PyInstaller打包后杀软误报中中中 使用代码签名证书（EV Code Signing）。提交主流杀软白名单审核。 提供免安装绿色版作为备选
R4PoC后需求不具普遍性中高高 先做3家PoC再投入Phase 2。PoC客户选择不同行业（军工+政府+企业）。 如2家以上反馈需求不匹配 → 调整产品方向或放弃
R5竞品快速跟进中中中 深耕行业Know-how（军工审计规则、闭环方法论）。与关键客户建立深度绑定。 如大厂入局 → 差异化定位"专注军工验收审计"
R6Win7环境Python 3.8依赖库不足低中低 全部选用纯Python实现或无C扩展的库。提前在Win7 VM验证依赖安装。 如有库不兼容 → 找替代方案或自实现
R7用户不接受浏览器形式低低低 浏览器自动打开并全屏，地址栏隐藏（通过--kiosk参数）。体验接近桌面应用。 如强需求 → Phase 3 评估WPF客户端
